# M7 — Remote hubs

**Goal:** attach to the work machine's hub from home, and see several hubs in one client.

**Exit criteria**

- The client keeps a list of hubs and shows all of them at once: the rail groups by hub, then project; the overview and the approvals panel cover every hub; new sessions and boards pick a hub.
- A hub is added from its connect link, or from a URL and token, and can be removed.
- `loom tunnel user@host` opens and keeps an SSH tunnel to a remote hub and prints the local address to add.
- A hub can listen on its Tailscale address as well as loopback.
- A hub refuses to listen on any other network address unless its config explicitly accepts unencrypted traffic.
- Repeated bad tokens from one address are cut off.
- Each hub keeps its own default and maximum levels, Steward setting, and platform, and the client respects them per hub.

## Design decisions

- **No custom encryption** (ADR-0008). Remote traffic goes through SSH or Tailscale. A hub listens on loopback, and optionally also on a tailnet address. Any other address needs `allowUnencryptedNetwork: true` and prints a warning.
- **The tunnel lives in the `loom` command**, not the hub, so it runs on the machine you sit at. It uses the remote port plus 10000 locally unless told otherwise, keeps `ssh -N -L` running with keep-alives, and reconnects with backoff. The desktop app (M9) will run the same code.
- **Hub identity is the hub id** from `welcome`, not its URL, so reaching the same hub two ways does not show it twice.
- **Tokens for other hubs are kept in the browser's local storage for now,** labeled per hub; the desktop app moves them to the OS keychain.
- **Failed logins are limited per remote address:** after 10 failures in 10 minutes that address is refused for 10 minutes. Loopback is limited too, so a local process cannot guess forever.
