# M12 — Polish, first slice

**Goal:** the daily-driver features the plan left for last: find anything a session said or did, review what sessions changed, and give terminal CLIs without hooks a state. Notifications and quiet hours already landed in M8 and M10. M12 stays open for further polish after this slice.

**Exit criteria**

- **History search.** Search the words of every session on every connected hub: messages, replies, tool calls, approvals, speech, errors. English and Portuguese, accents ignored. A result opens the session at that moment. Sessions and the Cockpit can search too (`search_history`, `loom search`).
- **Diff review.** Each session in a git folder has a Changes view: files, hunks, added and removed lines, against `HEAD` (uncommitted) or, for worktree sessions, against the branch's base. A person can revert a hunk or a file while the session is not working. After each turn the session records which files changed (`files.changed`), shown as a count in its header.
- **Heuristic manifests.** TOML manifests describe a CLI's screen: which programs they apply to and patterns that mean working, blocked, or idle. The hub matches them against the terminal's last lines, off the output path, only for manifests the hub owner enabled, and labels the result `heuristic`.

## Design decisions

- **The search index is a projection** (ADR-0003): an FTS5 table next to the event log, filled on append and rebuilt from the log when it is missing or its version changes. No new source of truth.
- **Search reads what a session can already read.** `session.read` already shows any session's history to sessions, so `history.search` is open to both roles.
- **Diffs come from git on demand,** not from the log: the working tree is the truth for "what changed". Only the per-turn summary (`files.changed`) is an event.
- **Reverts are a person's action,** never a session's or the Cockpit's, refused while the session is working, and checked against a hunk id so a stale screen cannot revert the wrong lines.
- **Manifests are data, not code** (ADR-0004, ADR-0011): the hub code never names a CLI. Matching runs at most once a second per session, on the screen as a headless terminal renders it (so redraws and cleared screens look as they do to a person). Sessions with pushed state (hooks) are never overridden.

- Tests: 336 passing, 2 skipped (live SDK). New:
  - Search: messages, tool calls, replies found by prefix with accents ignored ("sessao" finds "sessão"), newest first, per session; tool output and thinking not indexed; hostile queries never throw; an existing log is indexed when first opened; session names attached.
  - Diffs on real git repositories: modified (two hunks), staged added, deleted, renamed, untracked, binary; branch mode against the start commit including commits; one-hunk revert, a stale hunk id refused, whole-file reverts of every kind ending with a clean `git status`; stable hunk ids; `files.changed` recorded after a turn and after a revert; reverts refused while working.
  - Manifests: loading, invalid and missing ids reported, program matching with paths and `.exe`; rule order; the rendered screen (colors, line redraws, clear screen) rather than raw bytes; a real `loom-pty` session running a fake CLI that went working → blocked (approval) → idle with provenance `heuristic`, and no further heuristic states after a pushed state.

  - Changes tab: "Changes 1", `math.js` +4 −0 in two hunks against the start commit. Reverting the first hunk with the two-step button removed only the `console.log`; `git diff` confirmed the other hunk remained.
