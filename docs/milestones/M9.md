# M9 — Desktop app and installers

**Goal:** install Loom on Linux and Windows as a desktop app that starts its own hub, stays in the tray, and replaces v1; hand the Windows installer to colleagues.

**Exit criteria**

- `desktop/` is a Tauri 2 app. On launch it attaches to a hub already running on the configured port, or starts the bundled one and signs in without a pasted token.
- Closing the window keeps the app and its sessions running in the tray; "Quit Loom" stops the hub it started, and nothing is left behind if the app dies.
- Holding `Ctrl+Shift+Space` anywhere triggers push-to-talk. The microphone works in the app's webview on Linux and Windows.
- Links to other sites open in the system browser; the hub page gets no access to Tauri APIs.
- `loom <command>` from any terminal runs the CLI (`loom list`, `loom tunnel …`) without opening a window.
- A `.deb` installs everything needed with no Node or Claude Code install: the app, Node, the hub, the client, `loom-pty`, `loom-voce`, and the Agent SDK's `claude` binary. Package name `loom`, so it upgrades v1.
- A Windows NSIS installer is built by CI with the same contents (minus `loom-voce`) and warns when Git for Windows is missing.

## Design decisions

- **Bundle Node, not a single executable.** The Agent SDK runs its own native `claude` binary, and the hub's `loom` shim and stdio MCP server need a Node runtime anyway, so a Node single-executable build saves nothing and would force the ESM hub into CommonJS. The hub is bundled to plain ES modules with rolldown and run by a shipped `loom-node`. ADR-0010 is updated.
- **One hub entry with subcommands:** `hub.mjs` runs the hub, `hub.mjs cli …` the `loom` CLI, `hub.mjs mcp` the stdio MCP server. Development keeps running the `.ts` files directly.
- **Desktop sign-in without files or new crypto:** the app starts the hub with a random `LOOM_DESKTOP_TOKEN` in its environment. The hub accepts it for that run only and removes it from its environment before starting sessions. A hub the app did not start uses the normal token prompt.
- **No orphan hubs:** a hub started with `LOOM_EXIT_WITH_STDIN=1` shuts down cleanly when its stdin closes, which happens when the app quits or dies, on every platform.
- **The page stays a web page.** The window loads the hub's own URL; no IPC capability is granted to it. The Rust side calls into the page only to deliver the global shortcut.
- **Linux webview media:** WebKitGTK needs media streams enabled and a permission handler; the app allows the microphone and notifications only for its hub's origin.

- Tests: 303 passing, 2 skipped (live SDK), plus 3 Rust tests in `desktop/src-tauri` (hub probe, tokens, names). New: the desktop sign-in token, the single-entry shim, and a test that bundles the hub and runs its hub, `cli`, and `mcp` entries outside the repository; resampling, whisper sound tags, and one-run tokens in the client.
- The bundle, run from `/tmp`: served the client, accepted the desktop token, wrote a `loom` shim pointing back into the bundle, and ran a Haiku chat session through the SDK's own `claude` binary that called `mcp__loom__whoami` ($0.04). With `LOOM_EXIT_WITH_STDIN=1` it stopped 6 ms after its stdin closed.
- The app on this machine (X11, WebKitGTK 2.52), with `XDG_CONFIG_HOME` and `XDG_DATA_HOME` in a temporary folder and the hub on port 7423, checked through window screenshots:
  - Start: the app started its hub and showed the client signed in, no token pasted. A terminal session on that hub ran `loom whoami` through the packaged shim.
  - Closing the window hid it and the hub kept answering; launching `loom` again showed the same window (single instance).
  - Killing the app stopped its hub ("app closed: stopping sessions…"); **Quit Loom** in the tray (clicked over D-Bus) did the same with the release build.
  - Attach: with a hub already on the port, the app started none and showed the connect form.
  - `loom list` and `loom help` from the app binary ran the CLI without a window.
  - Push-to-talk: `Ctrl+Shift+Space` sent through XTest while the window was hidden brought it up, the microphone permission was granted for the hub page, and whisper transcribed the room ("[Paper rustling]", now dropped as a sound tag). Three problems found and fixed on the way: WebKitGTK never asks for the microphone for a hidden page (the shortcut now shows the window), `MediaRecorder`/`decodeAudioData` never finished there (capture now uses Web Audio in every browser, rechecked in Chromium with the JFK clip), and a hung microphone left the voice bar stuck (8 s timeout).
  - The one-run desktop token was saved by the client at first, so a later attach showed "rejected"; it is now never saved.
- `npm run desktop:build` made `Loom_2.0.0_amd64.deb`: 151 MB (356 MB installed), package `loom` 2.0.0, which would upgrade the installed v1 (`loom` 1.14.0). Contents: `/usr/bin/{loom, loom-node, loom-claude, loom-pty, loom-voce}`, `/usr/lib/Loom/{hub, client}`, icons, desktop entry. Not installed here.
