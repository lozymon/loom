# M1 — Hub, Claude SDK adapter, browser chat

**Status:** done 2026-09-12, except task 0 (work machine). Verified end to end in a browser against a real Claude session: an Edit and a Bash approval, a clarifying question, a hub restart with the browser reconnecting on its own, resume with the conversation intact, and two tabs showing the same live state.

**Goal:** run one or more Claude sessions from a browser against a local hub, resume them after a hub restart, and see messages, tools, and cost. Local only, Linux first, code kept platform-neutral.

**Size:** about one week.

**Exit criteria**

- `npm run hub` starts a hub on localhost with a token printed once. *(Also `npm run hub:dev` with data in `.loom-dev/`.)*
- `npm run client` opens a browser client that connects, lists sessions, and creates a Claude session in a chosen directory.
- The session streams assistant text, tool calls with results, and cost.
- Permission prompts and questions show as cards with Allow and Deny, and Answer for questions. This is the minimum needed to use a session; rules, "allow always", and timeouts are M3.
- Stopping and restarting the hub keeps the session list; sending to an old session resumes it.
- A second browser tab sees the same live state.
- Hub tests run without a model, through a fake adapter.

## Out of scope for M1

Rules and policy files, "allow always", timeouts, Steward, Cockpit tools, PTY sessions, worktrees, board, remote access, voice, desktop shell, Windows CI.

## Notes from building it

- The event log uses Node's built-in `node:sqlite` instead of `better-sqlite3` (ADR-0003).
- `session.created` carries the original spec so a resumed engine keeps its role and model; `session.live` and `session.engine` events were added to the protocol; `hub.snapshot` gives clients a consistent starting point.
- "Always allow" is wired through, since the SDK already provides the rule to persist; policy files remain M3.
- `assisted` currently behaves like `supervised`: prompts go to a human until the Steward exists (M5).
