# M2 — Terminal sessions, Claude's TUI, hooks, Windows CI

**Status:** done 2026-09-12, with one gap: the CI workflow exists but has never run, so nothing has executed on Windows yet.

**Goal:** any command runs as a terminal session beside Claude chat sessions, Claude's own TUI can run in a terminal with its state and approvals flowing into Loom, and every change is built and tested on Linux and Windows.

**Exit criteria**

- A "Terminal" session runs the login shell, or a given command, in a real PTY and renders in xterm in the browser.
- Reconnecting or opening a second tab shows the recent screen and keeps streaming, with no gaps or duplicate output.
- A process exit shows the exit code; Restart runs it again.
- "Claude (terminal)" runs `claude` in a PTY. Its working, idle, and engine session id come from Claude Code hooks. Its permission prompts and questions appear as Loom approval cards and are answered from Loom.
- "Open in terminal" on a chat session continues the same conversation in Claude's TUI. The chat session refuses to send while the terminal is running.
- CI builds and tests on ubuntu-latest and windows-latest.

## Design decisions

- **PTY sidecar protocol:** JSON lines over the sidecar's stdin and stdout. One sidecar process serves every terminal on a hub. Output is coalesced to at most one frame per 16 ms per terminal and 64 KB per frame, with bounded channels so a slow hub throttles the child instead of growing memory (v1 `pty.rs`). When the hub's pipe closes, the sidecar kills its children and exits.
- **Terminal bytes never enter the event log** (ADR-0003). The hub keeps the last 1 MB per terminal in memory. Clients `terminal.attach` and receive that tail plus a byte offset, then `term` frames with offsets, so reconnect has no gap and no duplicates.
- **Shell and command selection is hub logic**, not sidecar logic: login shell `-l` on Unix, PowerShell on Windows, programs found on PATH spawned directly on Windows to avoid v1's PowerShell-under-ConPTY deadlock.
- **Claude hooks are HTTP hooks** passed with `claude --settings <file>`, posting to `/hooks/<session>` on the hub with a per-session bearer token. Nothing is written to the user's own Claude settings. `PermissionRequest` and `PreToolUse` for `AskUserQuestion` wait for a Loom decision; if the hub is unreachable Claude falls back to its own prompt.
- **Last resize wins** when several clients show the same terminal.
- **Terminals do not survive a hub restart.** A running terminal becomes ended on restart; Restart relaunches it, and Claude terminals resume their conversation.

## Notes

- Claude Code holds hooks back until a folder is trusted, so `SessionStart` can be missed. Fixed by reading the session id from every hook and starting Claude terminals as idle.
- Real-sidecar tests cover output, environment, exit codes, resize, Unicode input, kill, a 5 MB flood with every byte checked, orphan cleanup when the hub side closes, and an end-to-end Claude terminal with a fake `claude` that posts real hook requests.
- Most sidecar tests only run on POSIX; Windows equivalents need a Windows machine or the CI run.
- Terminal sessions take their permission level at launch; changing it applies on the next restart.
- Accepting the trust dialog for a folder is recorded in the user's Claude Code configuration, as it would be in a normal terminal.
